# Lab 06 — Category-Partition ба PICT

**Оюутны нэр:** [М.Алтан-Од]
**Оюутны код:** [B222270023]  
**Хичээл:** F.CSA313 — Программ хангамжийн чанарын баталгаа ба тест

## Хэсэг A — Category-Partition

### A1. Сонголт ба төлөөлөх утгууд

Тестийн загварыг `POST /transfer` шилжүүлгийн функцийн тодорхойлолтод үндэслэн боловсруулав.

| Параметр | Сонголт | Төлөөлөх утгууд |
|---|---|---|
| From | Дансны төлөв | Valid, Frozen, Missing |
| To | Хүлээн авагчийн төлөв | Valid, Missing, SameAsFrom |
| Amount | Шилжүүлгийн дүн | Normal, Zero, OverBalance, OverLimit |
| Currency | Валютын хамаарал | Same, Different |

**Далд орчны сонголтууд:** дансны үлдэгдэл, өдрийн лимитийн үлдсэн хэмжээ, данс тус бүрийн валют, мөн данс царцаагдсан эсэх. Эдгээр нь тестийн үр дүнд нөлөөлөх тул тохиргоо буюу тестийн орчны хэсэгт тодорхой заана.

### A2. Хязгаарлалт ба тооцоо

**Алдааны давуу эрэмбэ:** From → To → Amount → Currency conversion. Нэг хүсэлтэд олон алдаа байвал хамгийн түрүүнд шалгагдах алдааг буцаана гэж тестийн oracle-д үзнэ. Энэ эрэмбэ нь өгөгдсөн тодорхойлолтод заагаагүй тул тестийн загварын таамаглал болно.

[ERROR] утгууд нь амжилтгүй үр дүн үүсгэх төлөөлөх утгууд. [SINGLE] хязгаарлалт нь нэг тестэд хамгийн ихдээ нэг алдааны утга оруулах зарчим. [IF] хязгаарлалт нь нөхцөл биелэх үед өөр сонголтын утгыг хязгаарлана.

Эхний бүрэн олонлогийн тоо:

`3 × 3 × 4 × 2 = 72`

**Хязгаарлалтын тэмдэглэгээ ба үндэслэл**

- `[ERROR]`: тухайн утга нь тодорхой алдааны нөхцөлийг төлөөлнө. `From = Frozen`, `From = Missing`, `To = Missing`, `To = SameAsFrom`, `Amount = Zero`, `Amount = OverBalance`, `Amount = OverLimit` нь алдааны утгууд юм.
- `[SINGLE]`: нэг тестийн мөрөнд хамгийн ихдээ нэг алдааны утга байна. Энэ нь алдаа тус бүрийн үр дүнг тусад нь шалгах боломж олгоно.
- `[IF]`: `From = Missing` бол `Amount = Normal`; `To = Missing` бол `Amount = Normal` байна. Данс байхгүй үед дүнгийн өөр алдааг давхар оруулахгүй гэсэн загварын хязгаарлалт юм.

**Хослолын тооцоо**

Эхний бүрэн хослолын тоо:

`N = 3 × 3 × 4 × 2 = 72`

`[IF]` хязгаарлалтыг хэрэглэсний дараа:

- `From = Missing`: `To`-ийн 3 утгаас `Amount = Normal` гэсэн 1 утга, `Currency`-ийн 2 утга боломжтой. `1 × 3 × 1 × 2 = 6`.
- `From = Valid` эсвэл `Frozen`, `To = Missing`: `Amount = Normal` тул `2 × 1 × 1 × 2 = 4`.
- `From = Valid` эсвэл `Frozen`, `To = Valid` эсвэл `SameAsFrom`: дөрвөн `Amount` утга боломжтой. `2 × 2 × 4 × 2 = 32`.

Иймээс `[IF]`-ийн дараах нийт тоо `6 + 4 + 32 = 42`.

`[SINGLE]`-ийг нэмж, нэг мөрөнд зөвхөн нэг алдааны утга зөвшөөрвөл:

- Алдаагүй мөр: `From = Valid`, `To = Valid`, `Amount = Normal`, `Currency = Same/Different` → 2.
- `From`-ийн алдаа (`Frozen`, `Missing`): тус бүрд 2 валют → 4.
- `To`-ийн алдаа (`Missing`, `SameAsFrom`): тус бүрд 2 валют → 4.
- `Amount`-ийн алдаа (`Zero`, `OverBalance`, `OverLimit`): тус бүрд 2 валют → 6.

Тэгэхээр хязгаарлалтуудын дараах тоо `M = 2 + 4 + 4 + 6 = 16`. Нийт боломжит хослол `72 → 42 → 16` болж буурна. Энэ тооцоо нь `[SINGLE]`-ийг бүх параметрийн алдааны утгад хатуу хэрэглэсэн загварын таамаглалд үндэслэнэ.

### A3. Тестийн тохиолдлууд

Тест бүрд дансны төлөв, шилжүүлгийн дүн, валютын тохиргоог урьдчилан бэлтгэнэ. `Normal` дүн нь эерэг бөгөөд үлдэгдэл болон өдрийн лимитэд багтсан байна. `OverBalance` нь хөрвүүлсний дараах дүн дансны үлдэгдлээс их боловч өдрийн лимитээс хэтрээгүй; `OverLimit` нь үлдэгдэл хүрэлцэх боловч өдрийн лимитийн үлдсэн хэмжээнээс их байна. Эдгээр нөхцөл нь алдааны ангиллыг тус тусад нь шалгах боломж олгоно.

| № | From | To | Amount | Currency | Тестийн зорилго | Хүлээгдэж буй үр дүн |
|---:|---|---|---|---|---|---|
| TC01 | Valid | Valid | Normal | Same | Энгийн амжилттай шилжүүлэг | HTTP 201, `{"result":"OK"}` |
| TC02 | Valid | Valid | Normal | Different | Валют хөрвүүлэлттэй шилжүүлэг | HTTP 201, `{"result":"OK"}` |
| TC03 | Missing | Valid | Normal | Same | Эх данс байхгүй | `ERROR_NO_FROM` |
| TC04 | Frozen | Valid | Normal | Same | Эх данс царцаагдсан | `ERROR_FROZEN` |
| TC05 | Valid | Missing | Normal | Same | Хүлээн авагчийн данс байхгүй | `ERROR_NO_TO` |
| TC06 | Valid | SameAsFrom | Normal | Same | Өөрийн данс руу шилжүүлэх | `ERROR_SAME_ACCOUNT` |
| TC07 | Valid | Valid | Zero | Same | Шилжүүлгийн дүн тэг | `ERROR_BAD_AMOUNT` |
| TC08 | Valid | Valid | OverBalance | Same | Дансны үлдэгдэл хүрэлцэхгүй | `ERROR_INSUFFICIENT` |
| TC09 | Valid | Valid | OverLimit | Same | Өдрийн лимит хэтэрсэн | `ERROR_LIMIT` |
| TC10 | Missing | Missing | Zero | Same | Эх данс, хүлээн авагч, дүнгийн алдаа давхцах | Таамагласан давуу эрэмбээр `ERROR_NO_FROM` |

**Тестийн oracle ба тайлбар**

- TC01–TC02 нь амжилттай шилжүүлгийн үндсэн болон валют хөрвүүлэлттэй хувилбарыг шалгана.
- TC03–TC09 нь алдааны долоон ангиллыг тус тусад нь шалгах тестүүд юм. TC03–TC09-ийн туршилтад бусад параметрүүдийг хүчинтэй байлгана.
- TC10 нь олон алдаа давхцсан үед аль алдааг буцаахыг шалгана. A2 хэсэгт тодорхойлсон `From → To → Amount → Currency conversion` эрэмбийн дагуу `ERROR_NO_FROM` хүлээнэ.
- TC10 нь `[SINGLE]` зарчмын энгийн тест биш, харин алдааны давуу эрэмбийг шалгах тусгай тест юм. Бодит системийн алдааны эрэмбэ өөр бол тестийн хүлээгдэж буй үр дүнг системийн тодорхойлолтод нийцүүлэн өөрчилнө.

Алдааны тестүүдэд HTTP статус болон хариуны бүтцийг системийн албан ёсны тодорхойлолттой тулган баталгаажуулна. Дээр дурдсан алдааны кодууд нь хүлээгдэж буй үндсэн үр дүн юм.

## Хэсэг B — PICT

PICT-ийн эх кодыг бүтээсэн нотолгоо `results/pict-build.txt` файлд хадгалагдсан. Туршилтын загварууд болон PICT-ээр үүсгэсэн үр дүнг тус тусад нь хадгалсан бөгөөд мөрийн тоог толгой мөрийг хасаж тооцов.

### B1. Browser загвар — хосын болон гурвалсан хамрах хүрээ

`browser.model` загварт дараах зургаан параметрийг тодорхойлсон.

| Параметр | Утгууд |
|---|---|
| Content | Allow, Restrict, Block |
| Cookies | Allow, Restrict, Block |
| Popups | Yes, No |
| Addons | Yes, No |
| Attacks | Yes, No |
| Forgeries | Yes, No |

Бүх боломжит хослолын тоо `3 × 3 × 2 × 2 × 2 × 2 = 144`.

PICT-ээр хоёр түвшний хосын хамрах хүрээ үүсгэхэд `results/browser-2way.txt` файлд 10 тестийн мөр, гурвалсан хамрах хүрээ үүсгэхэд `results/browser-3way.txt` файлд 20 тестийн мөр гарсан.

| Арга | Тестийн мөр | Бүх хослолтой харьцуулсан хэмжээ |
|---|---:|---:|
| Бүх боломжит хослол | 144 | 100% |
| 2-way | 10 | Ойролцоогоор 6.9% |
| 3-way | 20 | Ойролцоогоор 13.9% |

2-way арга нь параметр бүрийн утгуудын бүх боломжит хосыг дор хаяж нэг удаа хамруулах зорилготой. 3-way арга нь гурван параметрийн утгын хослолыг хамруулах тул илүү олон мөр шаарддаг ч илүү өргөн хамрах хүрээ өгнө. Иймээс тестийн тоо 10-аас 20 болж өссөн. Гэсэн хэдий ч эдгээр нь бүх 144 боломжит хослолыг бүрэн шалгасан гэсэн үг биш. PICT-ийн үүсгэсэн мөрүүдийг `results/browser-2way.txt` болон `results/browser-3way.txt` файлуудаас шалгаж болно.

### B2. Transfer загваруудын харьцуулалт

Шилжүүлгийн загварт `From`, `To`, `Amount`, `Currency` гэсэн дөрвөн параметр ашигласан.

| Загвар | Үр дүнгийн файл | Тестийн мөр |
|---|---|---:|
| Хязгаарлалтгүй | `results/transfer-nc.txt` | 13 |
| IF хязгаарлалттай | `results/transfer.txt` | 12 |
| Сөрөг утгуудтай | `results/transfer-neg.txt` | 16 |

**Хязгаарлалтгүй загвар (`transfer-nc.model`)**

Энэ загвар нь дөрвөн параметрийн утгуудыг тусгай `IF` хязгаарлалтгүйгээр авч үзсэн. PICT 13 мөр үүсгэсэн. Жишээлбэл, `Missing / Missing / OverBalance / Different` мөрөнд эх данс, хүлээн авагч болон шилжүүлгийн дүнтэй холбоотой хэд хэдэн асуудал зэрэг байна. Ийм тест нь олон алдаа давхцах үед системийн хариу хэрхэн сонгогдохыг шалгахад хэрэгтэй боловч аль алдаа эхэлж илрэхийг дангаараа тодорхойлохгүй.

**IF хязгаарлалттай загвар (`transfer.model`)**

Энэ загварт дараах нөхцөлийг нэмсэн.

- `From = Missing` үед `Amount = Normal`.
- `To = Missing` үед `Amount = Normal`.

Эдгээр нөхцөл нь данс байхгүй тохиолдолд дүнгийн өөр алдааг давхар оруулахгүй байх загварын сонголт юм. Үүний үр дүнд PICT 12 мөр үүсгэсэн. Хязгаарлалтгүй загвартай харьцуулахад нэг мөрөөр цөөрсөн. Энэ нь хязгаарлалт нэмэх бүрд тестийн тоо заавал их хэмжээгээр буурна гэсэн үг биш бөгөөд үр дүн нь загварын утгууд, хязгаарлалт болон PICT-ийн үүсгэх хамрах хүрээнээс хамаарна.

**Сөрөг утгатай загвар (`transfer-neg.model`)**

Энэ загварт `~Frozen`, `~Missing`, `~SameAsFrom`, `~Zero`, `~OverBalance`, `~OverLimit` зэрэг сөрөг утгуудыг ашигласан. PICT 16 мөр үүсгэсэн бөгөөд 14 мөр нэг сөрөг утгатай, 2 мөр сөрөг утгагүй байна. Энэ загвар нь хүчинтэй утгуудын ердийн хослолыг шалгахаас гадна параметр бүрийн буруу утгад систем хэрхэн хариулахыг шалгахад чиглэнэ. `~` тэмдэглэгээ нь тестийн загварын хэсэг болохоос API хүсэлтэд яг тэр тэмдэгттэй утга илгээх заавар биш юм.

**Гурван загварын дүгнэлт**

Хязгаарлалтгүй загвар 13, IF хязгаарлалттай загвар 12, сөрөг утгатай загвар 16 тестийн мөр үүсгэсэн. Эдгээр тоо нь загвар бүрийн зорилго өөр учраас шууд аль нэгийг нь хамгийн сайн гэж дүгнэхэд хангалтгүй. Хязгаарлалтгүй загвар нь давхардсан алдаатай нөхцөлийг судлахад, IF загвар нь тодорхой нөхцөлд боломжгүй гэж үзсэн хослолыг хасахад, сөрөг утгатай загвар нь буруу оролтыг шалгахад тусална. Бодит системийн тестэд эдгээр аргыг хэрэгцээнээс хамааран хамтад нь ашиглаж болно.

### B3. PICT-ийн мөрөөс сонгосон тестийн жишээ

Доорх хүснэгт нь PICT-ийн үүсгэсэн мөрүүдэд үндэслэсэн тестийн жишээг харуулна. API-ийн тодорхойлолтод заагаагүй HTTP статус болон алдааны кодыг таамгаар оноохгүй; системийн бодит тодорхойлолттой тулган баталгаажуулна.

| Тест | Загварын утгууд | Орчны тохиргоо | Хүсэлтийн утгууд | Хүлээгдэж буй үр дүн |
|---|---|---|---|---|
| PICT-TC01 — Амжилттай шилжүүлэг | `Valid / Valid / Normal / Same` | Эх данс царцаагдаагүй; үлдэгдэл болон өдрийн лимит хүрэлцээтэй; хоёр дансны валют ижил | Хүчинтэй эх данс, өөр хүлээн авагч, эерэг дүн | Шилжүүлэг амжилттай болж, тодорхойлолтод заасан амжилтын хариу буцна |
| PICT-TC02 — Нэг сөрөг утга | `Valid / Valid / ~Zero / Same` | Хоёр данс хүчинтэй; үлдэгдэл болон өдрийн лимит хүрэлцээтэй | `Amount` параметрт зөвшөөрөгдөөгүй утгын ангиллыг төлөөлөх оролт | Систем буруу оролтыг татгалзаж, тодорхойлолтод заасан алдааны хариу буцаана |
| PICT-TC03 — Эх данс байхгүй | `Missing / Valid / Normal / Same` | Хүлээн авагч хүчинтэй; дүн хэвийн; валют ижил | Эх данс заагаагүй хүсэлт | Систем эх данс байхгүй гэсэн алдааг тодорхойлолтын дагуу буцаана |

**Тестийн жишээг хэрэгжүүлэх тэмдэглэл**

`Valid`, `Normal`, `Same` зэрэг утгууд нь загварын төлөөлөх утгууд юм. Бодит туршилтад тэдгээрийг тестийн орчин дахь дансны дугаар, дүн, валют зэрэг тодорхой өгөгдөлтэй холбоно. `Missing` нь шаардлагатай өгөгдөл байхгүй нөхцөлийг, харин `~Zero` нь сөрөг тестийн загвар дахь хүчингүй утгын ангиллыг төлөөлнө. Бодит хүсэлтэд ашиглах яг утга, HTTP статус болон алдааны кодыг API-ийн албан ёсны тодорхойлолтоор тогтооно.

## Дүгнэлт

Category-Partition арга нь системийн оролтын параметрүүд болон тэдгээрийн төлөөлөх утгуудыг тодорхой бүтэцтэйгээр ангилахад тусалсан. Энэ аргаар шилжүүлгийн дөрвөн параметрийг тодорхойлж, алдааны ангилал болон хязгаарлалтуудыг загварчилсан. Эхний 72 боломжит хослол `[IF]` болон `[SINGLE]` хязгаарлалтыг хэрэглэснээр загварын таамаглалын хүрээнд 16 мөр болж буурсан. PICT нь параметрийн хослолуудаас тестийн багцыг автоматаар үүсгэх боломжийг харуулсан. Browser загварын 2-way арга 10 мөр, 3-way арга 20 мөр үүсгэсэн бөгөөд бүрэн хослолын тоо 144 байв. Энэ нь хамрах хүрээний зорилгоос хамааран тестийн тоо өөрчлөгдөхийг харуулж байна. Transfer загварт IF хязгаарлалттай хувилбар 12 мөр, хязгаарлалтгүй хувилбар 13 мөр үүсгэсэн. Сөрөг утгатай загвар 16 мөр үүсгэж, буруу оролтын ангиллыг шалгах боломж нэмсэн. Гэхдээ PICT-ийн үүсгэсэн тестийн мөрүүд нь системийн зөв ажиллагааг өөрсдөө батлахгүй тул хүлээгдэж буй үр дүнг тодорхойлолттой тулган бодитоор ажиллуулах шаардлагатай. Иймээс Category-Partition аргыг тестийн нөхцөлөө тодорхойлоход, PICT-ийг хослолын тестийн багц үүсгэхэд хамтад нь ашиглах нь үр дүнтэй.
